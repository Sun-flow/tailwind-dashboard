# Design Spec — Influencer Dashboard

> **Last updated**: 2026-10-20
> **Status**: Binding. This is the single source for how the dashboard looks and is built.
> If something here is wrong or missing, change this file (and log it in `resources/decisions.md`) instead of adding a rule somewhere else.

Inputs this spec is built from:

- `resources/profile.md` — who the client is (persona, 3 products, 5 platforms, 15% commission).
- `resources/brief.md` — the original three-block brief (a menu of what good dashboards show).
- `resources/mock-data-plan.md` — the data schema behind `data.js`.
- `resources/decisions.md` — the log of decisions and why they were made.

---

## 1. Decisions at a glance

| Topic | Decision |
|---|---|
| Pages | One page. No extra pages and no hamburger/sidebar. In-page section links are fine. |
| Navigation | Sticky header: title, links to KPIs / Drivers / Details, a theme toggle. Active link gets `aria-current`. |
| Theme | **Dark by default**, light via the toggle. The saved choice wins; with no saved choice the page is dark. |
| Styling | Tailwind CSS v4 browser build from the CDN. No build step. |
| Charts | Charts.css for KPI and driver charts. Sample data, focus on hierarchy and readability. |
| Data | `data.js` sets `window.DATA` (generated by `scripts/generate-data.py`). `app.js` renders it and computes no rollups. |
| JavaScript | The page renders from JS. There is no "works without JS" requirement. |
| Revenue scope | Affiliate commissions only. YouTube ad revenue and Twitch subscriptions are out of scope for now. |
| Trend period | Every trend badge compares the latest month with the month before ("vs last month"). |

## 2. Dependencies (pin exact versions)

```html
<style type="text/tailwindcss">
  @custom-variant dark (&:where(.dark, .dark *));
</style>
<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4.3.3"></script>
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/charts.css@1.2.0/dist/charts.min.css">
```

No other CSS or JS libraries.

### Allowed exceptions (the only ones)

1. The one `<style type="text/tailwindcss">` block above, holding only the `dark` variant line.
2. Inline `style` for **data-driven values only**: Charts.css `--size`, `--color` and `--labels-size`.
3. One small inline `<script>` in `<head>` that applies the saved theme before first paint.

Everything else is Tailwind utility classes. Prefer Tailwind's scale (`min-h-11`, `min-w-72`, `h-64`) over arbitrary `[...]` values.

## 3. Colour tokens

Write every class light-first with its `dark:` pair. Use these pairs and nothing else for these roles.

| Role | Classes |

| Page | `bg-gray-50 dark:bg-slate-900 text-gray-900 dark:text-slate-100` |
| Card surface | `bg-white dark:bg-slate-800 border border-gray-200 dark:border-slate-700` |
| Heading text | `text-gray-900 dark:text-slate-100` |
| Body text | `text-gray-600 dark:text-slate-300` |
| Muted text (labels, captions) | `text-gray-500 dark:text-slate-400` |
| Divider | `divide-gray-200 dark:divide-slate-700` / `border-gray-200 dark:border-slate-700` |
| Table header row | `bg-gray-50 dark:bg-slate-700/50` |
| Hover row | `hover:bg-gray-50 dark:hover:bg-slate-700/40` |
| Focus ring | `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-sky-500` |
| Active nav link | `text-sky-700 dark:text-sky-400` |
| Funnel segments (one hue, darkest = furthest step) | bought `indigo-700` / dark `indigo-300`; clicked, didn't buy `indigo-400` / dark `indigo-500`; saw, didn't click `gray-300` / dark `slate-600`. Bars set them as `[--color:var(--color-indigo-700)] dark:[--color:var(--color-indigo-300)]` (the only arbitrary-property classes, because inline `--color` can't follow the theme); legend swatches use the matching `bg-` classes |
| Alert severity pill | high `bg-red-100 text-red-800 dark:bg-red-500/15 dark:text-red-300`; medium `bg-amber-100 text-amber-800 dark:bg-amber-500/15 dark:text-amber-300`; low `bg-gray-100 text-gray-700 dark:bg-slate-700 dark:text-slate-300` |

### KPI accents (one per KPI category, nothing else)

| Category | Accent | Icon chip | Chart `--color` |
|---|---|---|---|
| Revenue | emerald | `bg-emerald-100 dark:bg-emerald-500/20` | `#10b981` (emerald-500) |
| Volume | sky | `bg-sky-100 dark:bg-sky-500/20` | `#0ea5e9` (sky-500) |
| Engagement | violet | `bg-violet-100 dark:bg-violet-500/20` | `#8b5cf6` (violet-500) |
| Performance | indigo | `bg-indigo-100 dark:bg-indigo-500/20` | `#6366f1` (indigo-500) |

A chart uses the accent of the metric it shows. Green and red are reserved for direction (trend badges, alerts); amber is reserved for medium-severity alerts.

### Contrast

All text meets WCAG AA (4.5:1) in **both** themes. Never put `gray-400`, `slate-500` or bare `green-500`/`red-500` text on a card or page background.

## 4. Type scale (five styles, nothing else)

| Style | Classes | Used for |
|---|---|---|
| Page title | `text-base sm:text-lg font-bold tracking-tight` | The one `<h1>`, in the sticky header |
| Section heading | `text-xl font-semibold` | Each block's `<h2>` |
| Card label | `text-xs font-semibold uppercase tracking-wide` + muted | Card titles (`<h3>`), KPI labels, table headers |
| KPI value | `text-3xl lg:text-4xl font-bold tracking-tight tabular-nums` | The big number on a KPI card |
| Body | `text-sm` + body or muted colour | Everything else, including table cells |

Font: Tailwind's default system sans-serif stack.

### Number formatting

- Currency: `$12,450` (no decimals) — `toLocaleString("en-US")`.
- Percentages: one decimal place, `23.3%`. Percentage-point changes: `+0.5pt`.
- Counts: thousands separators, `1,404`; large counts may be compacted, `3.3M`.
- Ratios (ROI): one decimal and an `x`, `2.8x`.
- Months: `Oct 2026`.
- A value that doesn't apply (e.g. saves on YouTube) shows a muted `—`.
- Numeric table columns are right-aligned with `tabular-nums`.

## 5. Layout and breakpoints

Mobile-first. Only three steps: base (under 768px), `md:` (768px+), `lg:` (1024px+). No `sm:` layout changes (small typography tweaks are fine).

| Block | Base | `md:` | `lg:` |
|---|---|---|---|
| Page container | `max-w-screen-xl mx-auto px-4` | `md:px-6` | `lg:px-8` |
| Block spacing | `space-y-8` | same | same |
| Sticky nav | Title left; links and toggle right; links stay on one row | same | same |
| KPI cards | `grid gap-4` (1 column) | `md:grid-cols-2` | `lg:grid-cols-4 lg:gap-6` |
| Driver charts | Sales funnel first, full width, above the grid (`#driver-lead`); then 1 column | same | funnel full width; grid `lg:grid-cols-2` |
| Detail tables | 1 column, `overflow-x-auto` | same | full width (`lg:col-span-2`) |
| Detail lists and alerts | 1 column | 1 column | `lg:grid-cols-2` |
| Card padding | `p-4` | `p-4` | `lg:p-6` |

Rules:

- No horizontal page scroll at any width from 375px up. Only a table wrapper (`overflow-x-auto`) may scroll sideways.
- Interactive elements are at least 44×44px (`min-h-11`, plus padding).
- Each anchored `<section>` has `scroll-mt-20` so the sticky header doesn't cover its heading.
- Grid for page and card layout; flex inside components.
- In a 2-column block (Drivers, Details), a card left alone on the last row spans the full width: `lg:*:last:odd:col-span-2` on the grid. Full-width tables still set `lg:col-span-2` themselves.

## 6. Components

Each component is **one render function in `app.js`**. Never hand-copy a component's markup; call its function. That is what keeps every instance identical.

| Function | Output |
|---|---|
| `card(title)` | `<article>` with card surface + `rounded-xl shadow-sm p-4 lg:p-6`, and a card-label `<h3>` |
| `kpiCard({label, value, sub, delta, accent, icon})` | Card with label + icon chip on one row, the KPI value, then the badge and a muted sub-line |
| `trendBadge(value, unit)` | Pill: `inline-flex items-center gap-0.5 whitespace-nowrap rounded-full px-2 py-0.5 text-xs font-medium` + up `bg-green-100 text-green-800 dark:bg-green-500/15 dark:text-green-300` or down `bg-red-100 text-red-800 dark:bg-red-500/15 dark:text-red-300`; text `▲ 32.8%` / `▼ 4.1%`, with `aria-label` "up 32.8% vs last month" |
| `barChart({label, rows, color})` | Charts.css bar chart (see §7) inside a `card()` |
| `barChart({title, ...})` options | `charts: [...]` stacks several charts under their own subtitles (used for product commission + conversion rate); `table` adds a breakdown table under the chart; `breakdown` adds a "Label: detail" list; `note` adds a muted footnote |
| `table({columns, rows})` | Table inside a focusable `overflow-x-auto` region: `w-full text-sm`; header row as tokens; `th`/`td` `px-3 py-3 whitespace-nowrap`; numeric columns `text-right tabular-nums`. A cell `{text, className, alerts}` shows `alertMarker()`s after its text. When columns overflow, a muted "Scroll sideways" hint appears under it |
| `dataTable({title, columns, rows})` | `table()` inside a full-width `card()` (`lg:col-span-2`) |
| `funnel({title, caption, rows, byPlatform, rates})` | Legend, then a Charts.css `bar multiple stacked` chart: one 100% bar for all platforms and one per platform, split into bought / clicked, didn't buy / saw, didn't click (shares of impressions from `derived.funnelMix`). Each row label shows the name plus "2.3% clicked" and "0.04% bought" lines (`--labels-size: 8rem`, rows `min-h-18`). Segments carry a `title` and screen-reader text. Then a muted note that each bar is 100% of impressions; "Each step by platform": one bar chart per step (`lg:grid-cols-3`, each on its own scale, with a note saying so); and a `table()` of step rates and raw counts |
| `severityBadge(severity)` / `alertMarker(alert)` | Alert severity pill (§3). The marker adds ⚠, `role="img"` and an `aria-label` with the alert message, and sits next to the related table row |
| `listCard({title, items, ordered})` / `list(...)` | Divided list; each item has an optional badge, text, muted meta line and right-aligned value. `ordered` numbers the items |

## 7. Charts.css usage

```html
<table class="charts-css bar show-labels data-outside data-spacing-10" style="--labels-size: 6.5rem">
  <caption class="sr-only">Commission share by platform</caption>
  <tbody>
    <tr>
      <th scope="row">Instagram</th>
      <td style="--size: 0.42; --color: #10b981"><span class="data">23.3%</span></td>
    </tr>
  </tbody>
</table>
```

- Rows **must** sit inside `<tbody>`; Charts.css only styles `tbody tr`. When building with `createElement`, create the `<tbody>` explicitly.
- `--size` is the value divided by the largest value, times 0.75, so the outside label of the biggest bar still fits at 375px.
- Value labels get `whitespace-nowrap` so short bars don't wrap them.
- Bars are linear, never log-scaled. A non-zero bar is at least 2px wide (`min-w-0.5`) so tiny values still show as a sliver; the value label carries the exact number.
- A chart with long value labels may lower the 0.75 factor (`scale` option).
- Percentages of impressions below 0.1% keep two decimals (`0.04%`) so they don't read as `0.0%`.
- Let the rows set the chart's height; don't wrap it in a fixed-height box. Charts.css sets `height: 100%`, so each chart sits in a plain `<div>`: otherwise it takes the height of the stretched grid card and pushes the content below it out of the card.
- One series colour per chart: the accent of the metric shown.

## 9. Theme toggle

- A native `<button>` in the sticky header labelled "Dark mode" (visible from `md:`, accessible name at all widths) with an `aria-hidden` icon: 🌙 when dark, ☀️ when light.
- `aria-pressed="true"` when dark is on.
- Clicking flips the `dark` class on `<html>` and saves `"dark"` or `"light"` to `localStorage` key `theme` (wrapped in `try/catch`).
- The `<head>` script applies the saved value before paint. No saved value means dark.

## 10. Accessibility and semantics

- One `<h1>`; `<header>`, `<nav aria-label>`, `<main>`, three `<section aria-labelledby>`, `<footer>`.
- `<h2>` per block, `<h3>` per card.
- Skip link to `#main`.
- Visible focus ring on every interactive element.
- Decorative icons and emoji are `aria-hidden="true"`; charts have a caption.
- Transitions respect `motion-reduce:transition-none`.

## 11. Definition of done (for any visual change)

1. `python3 server.py` serves `/` with status 200 and there are no console errors.
2. Screenshots at 375, 768, 1024 and 1440px in both themes look right against this spec.
3. No horizontal page scroll at any of those widths.
4. AA contrast in both themes; keyboard focus visible.
5. Every number shown comes from `window.DATA`.
6. If `scripts/generate-data.py` changed, regenerate `data.js` and confirm all invariant checks pass.
