# Context

> **Last updated**: 2026-10-20

## What this is

A one-page reporting dashboard for a fictional multi-platform influencer. It shows commissions, sales, conversions and engagement from five platforms and three affiliate products, top to bottom from outcomes (KPIs) to causes (Drivers) to the rows behind them (Details). The persona and products are in `resources/profile.md`.

It is a presentation piece built on generated mock data. It is **not** a product: there are no real APIs, no auth, no database, no deployment. The client is mae, who owns the repo and makes the design calls.

## Stack

- Static `index.html` + `app.js`, vanilla JavaScript, no framework and no build step.
- Tailwind CSS v4 browser build and Charts.css, both from the CDN at the exact versions in the spec (§2). No other libraries.
- `data.js` sets `window.DATA`. It is generated by `scripts/generate-data.py` (Python 3, standard library only).
- `server.py`: a small Flask server for the static files, port 3000, caching off. Flask is the only dependency (`requirements.txt`).

## Commands

```bash
pip3 install -r requirements.txt    # one-time
python3 server.py                   # serve at http://localhost:3000
python3 scripts/generate-data.py    # regenerate data.js; runs the invariant checks
python3 scripts/check-memory.py     # check the memory bank for broken paths and size
```

There are no tests or CI. "Done" for a visual change is the checklist in spec §11.

## How it fits together

`scripts/generate-data.py` → `data.js` (`window.DATA`, every rollup precomputed) → `app.js` renders it into the three `<section>` blocks of `index.html`. `app.js` computes nothing: a new number means a new field in the generator, with an invariant check. The theme is a `dark` class on `<html>`, set before first paint by a small inline script.
